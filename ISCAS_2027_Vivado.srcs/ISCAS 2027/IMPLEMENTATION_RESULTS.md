## Empirical budget / max-interval sweep (Python only)

`run_budget_sweep.py` was run with the fixed nine-stimulus suite at 1.0 s duration and 0.1 ms timestep. It swept empirical refresh triggers of 1, 10, and 100 μV and maximum cache ages of 4 and 16 samples. The output is `results/metrics/area_followup_python/empirical_budget_sweep.csv`, with reproducibility details in `results/metrics/area_followup_python/budget_sweep_metadata.json`.

All 54 stimulus/configuration cases completed without the model's numerical runaway guard. Each case compared the 10,000 post-initial state updates against the full-update Euler reference. The baseline denominator is 60,006 Python ionic-current function evaluations per stimulus (six terms at 10,001 time-grid points); the total denominator per nine-stimulus group is 540,054. Voltage and current errors below are observed differences on this provisional model, not guaranteed bounds.

## Matched-target held-out policy comparison and RTL operand isolation

`run_heldout_scheduler_experiments.py` used a fixed 10 μV maximum-observed-error criterion to select configurations on the existing nine training stimuli only, then evaluated six deterministic held-out traces: changed step timings, double pulse, triangular ramp, rapid pulse train, and chirped light. Both policies use the same initial state, input samples, parameters, and 1 s/0.1 ms grid as their full-update reference.

| Policy selected on training data | Training max error | Training pooled RMS / MAE | Training evaluation reduction | Held-out max error (worst input) | Held-out pooled RMS / MAE | Held-out evaluation reduction | Held-out count over 10/50/100 μV |
|---|---:|---:|---:|---:|---:|---:|---:|
| Per-current sensitivity (`1e-14 A`, max age 16) | 1.39259 μV | 0.16298 / 0.07661 μV | 57.73% | 1.48659 μV (triangle ramp) | 0.21603 / 0.08455 μV | 38.08% | 0 / 0 / 0 |
| Accumulated voltage proxy (`1e-6 V`, max age 16) | 7.21549 μV | 0.34871 / 0.09583 μV | 52.38% | 6.97410 μV (chirped light) | 0.31175 / 0.04978 μV | 33.00% | 0 / 0 / 0 |

On these six held-out inputs, sensitivity had lower max/RMS error and higher Python current-function reduction; the accumulated proxy had lower pooled MAE. Both stayed below the selected observed-error target in this finite test. Neither result is a guaranteed bound or evidence of hardware savings or biological accuracy. The sensitivity scheduler selected in Python is **not** implemented in RTL.

The current RTL change is an operand-isolation option in `photoreceptor_adaptive.v`, enabled by default and exposed as `OPERAND_ISOLATION_ENABLE` on `photoreceptor_top`. Six sets of voltage/gate/calcium operands are snapshotted on accepted refreshes; between refreshes the combinational current modules receive those held operands. The existing global refresh policy and equations remain intact. `OPERAND_ISOLATION_ENABLE=0` bypasses operand isolation for an adaptive A/B run; `ADAPTIVE_ENABLE=0` still selects the unchanged baseline. No RTL activity, simulation, area, timing, or power conclusion is available yet.

`current_update_scheduler.v` now clamps the effective refresh interval to the 16-bit counter range and saturates that counter. Adaptive recomputation count also saturates rather than wrapping. Static source checks only; manual compile/simulation is required.

The held-out CSV, JSON configuration, and plot are under `results/metrics/heldout_scheduler/`. Five additional 40-cycle Q16.24 baseline vectors were exported to `results/rtl_reference_vectors/` for alternating and held-out step/pulse/ramp/rapid patterns. `tb_photoreceptor_baseline_trace` now includes these with the original dark/step/pulse vectors; all eight trace cases are pending Vivado execution.
